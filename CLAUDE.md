## Project overview

An **Adobe Acrobat JavaScript Add-in** (single file: `lesezeichen_sortierer.js`) that:

1. Reads all bookmarks from the open PDF
2. Sorts the physical PDF pages to match the bookmark order
3. Removes any existing "Automatisches Inhaltsverzeichnis" (+ its PDF pages)
4. Inserts a freshly generated table-of-contents at the front, with text fields for title and page number per entry
5. Registers a menu item under **View → PDF nach Lesezeichen sortieren**

## Installation

Paste the script into Adobe Acrobat's **JavaScript console** (Ctrl+J) or install it as a folder-level script:
`%APPDATA%\Adobe\Acrobat\<version>\JavaScripts\lesezeichen_sortierer.js`

After restart the menu item appears under **View**.

## Technology

- **Language:** Adobe Acrobat JavaScript (based on ES3/ECMA-262; Acrobat JS API)
- **Key Acrobat APIs used:**
  - `app.trustedFunction` / `app.beginPriv` / `app.endPriv` — elevated privileges for page manipulation
  - `this.bookmarkRoot` — bookmark tree traversal
  - `bm.execute()` / `this.pageNum` — resolve bookmark target page (see Known Issues #1)
  - `this.movePage()` / `this.newPage()` / `this.deletePages()` — physical page manipulation
  - `this.addField()` — draw text fields for the TOC
  - `app.addMenuItem()` — register menu entry
- **No build step, no dependencies**

## Known issues / open items

All items below are **accepted risks** — they are safe for BelegTool (DigitalerUnterlagenOrdner) PDFs, which are the only documents this script is used with. None of these should be "fixed" without a specific trigger (noted per item).

| # | Issue | Location | Fix when |
|---|---|---|---|
| 1 | `getBookmarkPage` uses `bm.execute()` — non-page bookmarks (JS/URL action) record the wrong page and can block the script mid-run. Correct API is `bm.pageNum` (no side effects) but BelegTool exports only page-navigation bookmarks. | `lesezeichen_sortierer.js:21-27` | If non-BelegTool PDFs with JS bookmarks need to be sorted |
| 2 | `movePage` loop relies on a forward-only invariant (blocks always move right). An offset bug would silently corrupt page order. The algorithm is structurally correct but the invariant is not enforced; a guard could be added. | `:350-355` | If stress-testing reveals a failure case |
| 3 | `uiPosition`-based offset recalculation is fragile for deeply-nested or out-of-order bookmarks — self-flagged. | `:360-379` | If non-standard bookmark structures need to be supported |
| 4 | Zero-length blocks (bookmarks on the same page as the next bookmark) are not guarded; `laenge = 0` causes `movePage` to be called 0 times, which is safe but untested at scale. | `:79-97, 350` | If stress-testing shows it fires |
| 5 | `deletePages` guard skips deleting the last page (guards `numPages > 1`); leaves a stale TOC page + bad offset if the TOC exactly fills the document. | `:253-257` | If single-page documents need TOC removal |
| 11 | `bereinigeDuplikate` keys `seitenMap` by raw page number (numeric). In ES3, object property lookup coerces to string, so `seitenMap[0]` → `"0"`. Prototype property names like `__proto__` would not realistically appear as page numbers, but using prefixed keys (`"p" + s`) would be safer. | `:59-76` | Low priority; add prefix `"p" + s` if ESLint or security review flags this |

Additional known constraints:

- Secondary (duplicate-page) bookmarks are **detected but not physically moved** — they appear in the TOC at the same page as their primary. The `insertChild` call was evaluated and intentionally left inactive: BelegTool's PDF structure correctly handles the current behaviour.
- No undo support — Acrobat's undo stack is cleared after `app.beginPriv` operations.
- The "Automatisches Inhaltsverzeichnis" detection is case-insensitive name matching; a renamed TOC will not be cleaned up.

## Future roadmap

### TOC with clickable links

Replace read-only text fields with **button fields** (`"button"` type). Buttons support an `OnMouseUp` action for page jumps:

```js
var btn = this.addField(feldName, "button", aktuelleIhvSeite, textRect);
btn.buttonSetCaption(datensatz.name);
btn.setAction("MouseUp", "this.pageNum = " + zielSeiteImPDF + ";");
```

Back-link on content pages:

```js
var backBtn = this.addField("BackToTOC_" + seite, "button", seite, backRect);
backBtn.buttonSetCaption("↑ TOC");
backBtn.setAction("MouseUp", "this.pageNum = 0;");
```

Open design questions before implementing: replace text fields entirely or overlay transparent button; back-link position; all pages vs. first page of block only.

### PDF split with cross-referenced TOC

Split the sorted PDF into multiple output files, each ≤ N pages. Splits always fall at a top-level block boundary. Each output file carries a full TOC with entries showing which file holds chapters not in the current file.

Algorithm sketch: walk `arbeitsliste` accumulating page count; split at block boundary when limit would be exceeded; use `this.extractPages()` per segment; inject cross-referenced TOC (local page numbers for own chapters, `"→ Datei X, S. Y"` for foreign chapters).

Open questions: how N is specified (dialog vs. fixed setting); output folder; filename convention; clickable cross-file links vs. plain text only.

## Acrobat JS engine — `this` context (important)

In standard browser/Node JavaScript, calling a plain (non-method) function sets `this` to the global object (`window` or `globalThis`). In **Adobe Acrobat's embedded JS engine** the document *is* the global object. This means `this` inside any function — regardless of nesting level — resolves to the current Doc object, not a detached global.

Consequence: helper functions like `loescheInhaltsverzeichnisUndBerechneOffset()` and `sortiereSeitenBloecke()` successfully call `this.deletePages()`, `this.movePage()`, etc. even though they are plain function calls, not method calls on a Doc instance. This works correctly in Acrobat and must not be "fixed" by passing a `doc` parameter — that would be an unnecessary change that adds noise without benefit.

This differs from how the same code would behave in a browser console or Node — do not apply standard JS linting rules about `this` to Acrobat scripts.
